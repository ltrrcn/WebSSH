# Feature Specification: WebSSH 基础版（网页端 SSH 终端）

**Feature Branch**: `001-webssh-base-terminal`

**Created**: 2026-09-26

**Status**: Draft

**Input**: User description: "开发一款 webssh，主要是网页端的 ssh 服务。不依赖任何外部数据库。既兼容 FnOS 模式也兼容 Linux 系统（其他系统）。基础版不依赖 sqlite，通过 log 做基础审计。后期增加高级版依赖 sqlite，支持审计等堡垒机能力。先完成基础功能。"

## Clarifications

### Session 2026-09-26 (UI 设计)

- Q: 页面整体布局采用什么形态？ → A: 左侧为主机列表（含新增主机入口），点击主机连接后右侧显示对应终端；不再使用顶部导航菜单。
- Q: 多个终端会话如何组织？ → A: 终端区顶部显示 tab 页，每个 tab 对应一个活动会话，可并存、可切换。
- Q: 关闭 tab 或页面时如何处理活动会话？ → A: 关闭 tab 前检查该会话是否仍在进行，未结束则弹出确认提示「是否关闭当前终端」；关闭页面（unload）前存在活动会话时同样提示。
- Q: 审计与令牌入口放哪里？ → A: 收纳到左下角「设置」入口中。
- Q: 主题要求？ → A: 支持黑色与白色主题切换；架构上预留后续导入终端配色方案（如 iTerm 配色）的扩展点。
- Q: 终端 tab 的会话操作入口？ → A: 右击 tab 弹出上下文菜单，提供「复制会话」（同一主机再开一个终端会话）与「关闭会话」。
- Q: 主机表单的认证术语与交互？ → A: 统一使用「密码」「密钥」术语；认证方式切换时仅显示对应输入框（密码框 或 私钥+私钥口令框）。
- Q: 会话备注名的行为？ → A: 双击顶部会话卡可修改备注名；每个会话分配临时 ID，备注按会话 ID 存储在浏览器本地（localStorage），不修改服务端主机名。
- Q: 复制会话后的交互？ → A: 复制的会话创建后立即进入改名编辑态；tab 栏末尾提供「＋新建会话」入口（弹出主机选择）；会话名修改时与现有会话名冲突则拒绝保存并提示。
- Q: 主机分组的折叠？ → A: 分组标题可点击展开/折叠，折叠状态持久化到浏览器本地。
- Q: 左侧列表的语义与右键入口？ → A: 左侧列表显示的是已保存的会话连接（主机+凭据的保存记录）；右键可弹出菜单「新建会话连接」，新建后保存到列表；会话条目右键提供 连接/编辑/删除/新建会话连接。

### Session 2026-09-26

- Q: 只读级别的 MCP 令牌，应当依据什么来判断一次操作是否被允许？ → A: 三层纵深判定并用其一票否决：A 能力级隔离（只读令牌不提供"执行任意命令"能力）+ B 内置只读命令白名单（默认拒绝）+ C 内置危险命令黑名单（对任何令牌兜底）
- Q: 只读级别令牌被允许「读取指定文件内容」时，可读取的路径范围应如何限定？ → A: 采用目录权限矩阵：系统敏感路径恒定全禁（读/写/下载/修改均不可，且不可被令牌配置放行）；系统级非敏感路径默认可读、可修改并可在矩阵中收紧；其余路径须在令牌中显式声明目录前缀才允许访问
- Q: 目录权限矩阵应当按什么作用域配置与生效？ → A: 每令牌独立配置，创建时以一组全局默认条目初始化，令牌只能在该基础上收紧，不得超出全局默认范围
- Q: 经由 MCP 令牌执行的操作，审计记录中应当保留命令原文的多少内容？ → A: 记录完整命令原文 + 输出摘要（前若干字节），并对二者执行敏感信息脱敏
- Q: 通过 MCP 令牌发起的命令若长时间不返回，系统应当如何处理？ → A: 设定单次执行时长上限，超时强制终止并回传已产生的输出摘要

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 从主机清单直接打开远程终端 (Priority: P1)

使用者登录 WebSSH 后，在已保存的主机清单中点击其中一台，浏览器内即出现一个可交互的远程终端；在终端中输入命令并回车，远程主机的输出立即回显，使用体验与本地终端一致。

**Why this priority**: 这是产品存在的根本理由。没有它，其余功能都无意义；单独交付它就已构成可用的最小产品。

**Independent Test**: 预置一台可登录的目标主机，点击后终端出现可输入提示符，执行一条简单命令并看到正确回显，即证明核心价值成立。

**Acceptance Scenarios**:

1. **Given** 使用者已登录且主机清单中有一台可达主机，**When** 点击该主机，**Then** 浏览器内出现可输入的远程终端，并显示远程主机的提示符。
2. **Given** 终端已打开，**When** 输入一条命令并回车，**Then** 远程主机的输出在终端中原样显示，包含换行与控制字符渲染。
3. **Given** 终端正在输出长内容，**When** 使用者调整浏览器窗口大小，**Then** 远程终端的行列数同步调整，输出不会错位。
4. **Given** 终端正在输出长内容，**When** 使用者按下中断组合键，**Then** 远程命令被中断，终端回到可输入状态。

---

### User Story 2 - 保存主机与凭据，一次录入反复使用 (Priority: P1)

使用者可以把常用主机录入清单（名称、地址、端口、登录用户名、认证方式），凭据随主机一并保存；保存后再连接无需重复输入凭据。清单支持新增、编辑、删除与分组。

**Why this priority**: 每次连接都手工填地址和口令会让产品失去意义；凭据的保存方式又直接决定安全风险，必须与终端能力同等优先。

**Independent Test**: 录入一台主机并保存凭据，退出后重新进入直接打开终端成功，即证明该故事独立可用。

**Acceptance Scenarios**:

1. **Given** 使用者在主机清单页面，**When** 填写主机信息并保存，**Then** 该主机出现在清单中，可立即用于发起连接。
2. **Given** 主机条目已保存凭据，**When** 使用者再次打开该主机的终端，**Then** 无需重新输入凭据即可完成登录。
3. **Given** 使用者查看或编辑已保存的主机，**When** 页面展示凭据相关字段，**Then** 明文凭据永不显示，且不出现在日志与错误信息中。
4. **Given** 某台主机已不再使用，**When** 使用者删除该条目，**Then** 该主机及其凭据被移除，不再可用于发起连接。

---

### User Story 3 - 会话可靠结束，不残留资源 (Priority: P2)

使用者关闭浏览器标签页、刷新页面或网络中断后，服务端立即感知并终止对应的远程连接，释放全部资源；长时间无操作的会话被自动断开。

**Why this priority**: 残留的远程连接既是资源泄漏，也是安全隐患；在长期运行的设备上会累积成实质问题。

**Independent Test**: 打开会话后直接关闭标签页，检查服务端与该会话相关的进程已全部退出；空闲会话在超时后被断开。

**Acceptance Scenarios**:

1. **Given** 一个进行中的终端会话，**When** 使用者关闭标签页，**Then** 服务端在数秒内终止对应远程连接，不残留进程。
2. **Given** 一个终端会话长时间无任何输入与输出，**When** 达到空闲时限，**Then** 会话被自动断开，终端提示断开原因。
3. **Given** 使用者同时打开多个会话，**When** 其中一个断开，**Then** 其余会话不受影响，继续正常工作。

---

### User Story 4 - 连接行为留痕，可追溯可导出 (Priority: P2)

每一次连接的建立、失败与断开都被记录为一条审计记录，包含操作者、时间、目标主机、认证方式、结果、时长与断开原因。使用者可以按时间顺序查看，并导出为可直接阅读的文件。

**Why this priority**: 谁在什么时候登过哪台机器是这类产品最基本的可追溯要求；基础版以日志留痕满足，不做复杂检索。

**Independent Test**: 连续发起成功、失败、空闲断开三类连接后，审计列表出现对应三条记录，且导出文件可被人工直接阅读。

**Acceptance Scenarios**:

1. **Given** 使用者成功连接一台主机并断开，**When** 查看审计记录，**Then** 存在一条含操作者、时间、目标主机、结果、时长的记录。
2. **Given** 一次连接因认证失败而未建立，**When** 查看审计记录，**Then** 仍存在一条记录，结果为失败并标明原因。
3. **Given** 使用者导出审计记录，**When** 打开导出文件，**Then** 内容按时间顺序排列且可被人工直接阅读。
4. **Given** 审计记录中包含失败的口令尝试，**When** 记录被写入与展示，**Then** 其中不含任何明文凭据。

---

### User Story 5 - 同一套程序在飞牛设备与通用 Linux 上都能跑 (Priority: P2)

同一套程序既能作为飞牛 fnOS 应用安装运行，也能在通用 Linux 系统上运行；两种形态下功能一致，数据目录由部署环境决定，使用者无需手工修改路径。

**Why this priority**: 目标用户横跨 NAS 用户与通用服务器用户，二者共用一套代码才能避免功能分叉。

**Independent Test**: 同一构建产物分别在飞牛设备与通用 Linux 上完成「录入主机 → 打开终端 → 执行命令 → 查看审计」全流程且结果一致。

**Acceptance Scenarios**:

1. **Given** 程序部署在飞牛 fnOS 上，**When** 使用者通过系统桌面入口打开，**Then** 可完成终端连接、主机管理与审计查看，且身份来自系统登录态。
2. **Given** 程序部署在通用 Linux 上，**When** 使用者通过浏览器访问，**Then** 可完成同样的全部功能，数据落在部署时指定的目录。
3. **Given** 程序在任一形态下启动，**When** 启动时所需数据目录不存在，**Then** 自动创建且仅限应用自身可读写。

---

### User Story 6 - 创建 MCP 令牌，让外部 AI 工具接入 (Priority: P2)

使用者可以创建一枚或多枚 MCP 令牌，为其命名并指定可访问的主机范围与操作级别；令牌创建后明文仅展示一次。使用者将令牌配置到外部支持 MCP 的 AI 工具后，该工具即可在令牌授权范围内查询主机清单、在指定主机上执行命令并取回输出。所有经由令牌发起的操作同样计入审计。

**Why this priority**: 这让产品从「人用终端」延伸到「AI 工具可用」，是重要的延伸价值；但它建立在 P1 的连接与主机管理能力之上，且一旦失控等同于把命令执行权交给外部程序，因此放在 P2 并要求完整的可控性设计。

**Independent Test**: 创建一枚限定范围的令牌，用外部 MCP 客户端凭该令牌查询主机并成功执行一条命令；随后撤销该令牌，客户端立即失效。

**Acceptance Scenarios**:

1. **Given** 使用者在令牌管理界面，**When** 填写名称、选择主机范围与操作级别并创建，**Then** 生成一枚令牌且明文仅在此次展示一次，此后不再可查看。
2. **Given** 一枚有效令牌已配置到外部工具，**When** 该工具查询主机清单，**Then** 仅返回该令牌授权范围内的主机。
3. **Given** 一枚操作级别为可变更的有效令牌，**When** 外部工具请求在授权主机上执行一条命令，**Then** 返回该命令的输出；请求授权范围外的主机时被拒绝。
4. **Given** 使用者撤销某枚令牌，**When** 外部工具再次使用该令牌，**Then** 请求立即被拒绝。
5. **Given** 外部工具通过令牌执行了命令，**When** 查看审计记录，**Then** 存在对应记录且标明经由哪枚令牌发起。
6. **Given** 一枚操作级别为只读的令牌，**When** 外部工具请求执行一条命令，**Then** 请求被拒绝并明确提示该令牌无执行命令的能力。
7. **Given** 一枚配置了目录权限矩阵的令牌，**When** 外部工具读取矩阵中声明为可读的目录内的文件，**Then** 返回文件内容；**When** 读取矩阵未覆盖的路径或系统敏感路径，**Then** 请求被拒绝并明确提示原因。

---

### Edge Cases

- 目标主机不可达或端口未开放时，系统在限定时间内给出明确的连接失败提示，不无限等待。
- 认证失败（口令错误、私钥不匹配）时，提示失败并允许重试，且失败尝试被审计记录。
- 首次连接某台主机且其身份指纹未被确认时，系统必须显式提示使用者确认后再继续，禁止静默接受。
- 已确认过的主机指纹发生变化时，系统必须拒绝连接并告警，防止中间人。
- 使用者刷新页面或网络闪断时，服务端终止会话并释放资源，审计记录断开原因。
- 终端输出极大体量内容（如输出整个大文件）时，界面保持可响应，使用者可中断。
- 来自未授权来源的终端连接请求被直接拒绝，不建立远程连接。
- 使用者尝试连接不属于自己的主机条目时被拒绝，且看不到该条目的凭据。
- 同时打开的会话数达到上限时，新的连接请求被拒绝并给出明确提示。
- 配置文件损坏或写入中断时，系统回退到最近一次备份启动，不静默清空数据。
- 令牌长期未使用或已超过设定有效期时自动失效，无需使用者手工清理。
- 操作级别为只读的令牌收到变更类命令请求时，请求被拒绝并明确提示权限不足。
- 命令请求中包含拼接执行语法（如分号、双与符号、管道、命令替换）时，一律按不可判定处理并拒绝，不尝试拆分后放行。
- 请求访问的路径包含向上穿越语法时，请求被拒绝，不按拼接后的字面路径判定。
- 请求路径经符号链接指向系统敏感路径时，按解析后的真实路径判定并拒绝。
- 令牌矩阵被配置为放行系统敏感路径时，系统忽略该配置并继续拒绝，配置界面同时给出提示。
- 命令原文或输出中夹带疑似口令、私钥片段时，审计记录以占位符替换该片段，其余内容照常保留。
- 输出体量超过摘要长度上限时，仅保留前若干字节并标记已截断。
- 命令执行达到时长上限被终止时，审计记录以「执行超时」为结束原因，远程连接随之释放。
- 外部工具在短时间内高频调用令牌时，超出限额的请求被拒绝，不影响其他令牌与使用者的正常会话。
- 令牌遗失时，使用者只能撤销后重建，系统不提供找回明文的能力。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 允许使用者从已授权主机清单发起终端会话，且仅能发起清单内的连接。
- **FR-002**: 系统 MUST 在浏览器内提供可交互终端，双向传输输入与输出，并正确渲染换行与控制字符。
- **FR-003**: 系统 MUST 在浏览器窗口尺寸变化时同步调整远程终端的行列数。
- **FR-004**: 使用者 MUST 能够新增、编辑、删除主机条目，并按分组组织。
- **FR-005**: 系统 MUST 加密保存凭据，任何界面、日志与错误信息均不得出现明文凭据。
- **FR-006**: 系统 MUST 支持口令与私钥两种认证方式，私钥可带口令保护。
- **FR-007**: 系统 MUST 校验目标主机身份指纹；未确认过的主机 MUST 经使用者显式确认后方可连接。
- **FR-008**: 系统 MUST 校验终端连接请求的来源，拒绝未授权来源。
- **FR-009**: 系统 MUST 保证使用者只能访问自己名下的主机条目与会话，不能访问他人数据。
- **FR-010**: 系统 MUST 为每个连接的生命周期事件生成审计记录，不得遗漏。
- **FR-011**: 审计记录 MUST 至少包含：操作者、时间、目标主机、认证方式、结果、时长、断开原因。
- **FR-012**: 审计记录 MUST 可按时间顺序查看，并可导出为可直接阅读的文件。
- **FR-013**: 系统 MUST 在会话结束（主动关闭、网络断开、空闲超时）时释放全部服务端资源，不残留进程。
- **FR-014**: 系统 MUST 为连接建立设置超时，为会话设置空闲超时，超时后给出明确反馈。
- **FR-015**: 系统 MUST 能以飞牛 fnOS 应用形态部署，也能在通用 Linux 系统部署，两种形态功能一致。
- **FR-016**: 系统 MUST 将所有持久化数据保存在部署环境指定的数据目录中，目录位置不得写死在程序内。
- **FR-017**: 系统 MUST 对持久化数据保留最近一次备份，并在数据损坏时自动回退。
- **FR-018**: 系统 MUST 在不依赖任何外部数据库与外部中间件的前提下完成上述全部功能。
- **FR-019**: 系统 MUST 限制单个使用者可同时打开的会话数量，防止资源耗尽。
- **FR-020**: 系统 MUST 拒绝连接主机清单以外的任意主机，禁止充当开放跳板。
- **FR-021**: 系统 MUST 在终端输出量过大时保持界面可响应，并支持使用者中断输出。
- **FR-022**: 系统 MUST 允许使用者创建、命名与撤销 MCP 令牌，并支持多枚令牌并存。
- **FR-023**: 系统 MUST 在令牌创建后仅展示一次明文，此后不得以任何形式回显，且 MUST 以不可逆方式保存校验信息。
- **FR-024**: 系统 MUST 允许为令牌指定可访问的主机范围与操作级别，默认按最小权限授予。
- **FR-025**: 系统 MUST 仅向令牌开放其授权范围内的主机，范围外的请求一律拒绝。
- **FR-026**: 系统 MUST 支持为令牌设置有效期，过期后自动失效；使用者 MUST 可随时撤销令牌，且撤销立即生效。
- **FR-027**: 系统 MUST 将经由令牌发起的每一次操作计入审计记录，并标明所使用的令牌。
- **FR-028**: 系统 MUST 对令牌调用施加频率限制，超额请求被拒绝。
- **FR-029**: 令牌 MUST NOT 绕过任何既有安全约束，主机授权清单、主机指纹校验与会话隔离对令牌同样生效。
- **FR-030**: 系统 MUST 对令牌发起的操作执行三层判定（能力隔离 → 只读命令白名单 → 危险命令黑名单），任一層不通过即拒绝，且三层 MUST 对只读与可变更两个级别同时生效。
- **FR-031**: 系统 MUST NOT 向只读级别令牌提供「执行任意命令」能力，该级别仅可调用只读类能力（如查询主机清单、读取指定文件内容）。
- **FR-032**: 系统 MUST 内置只读命令白名单；只读令牌引发的命令仅允许白名单内的条目，未列入者默认拒绝，且白名单 MUST NOT 包含任何可改变系统状态的命令。
- **FR-033**: 系统 MUST 内置危险命令黑名单；任何令牌（含可变更级别）的命令请求命中黑名单时 MUST 被拒绝，不得因级别更高而放行。
- **FR-034**: 系统 MUST 将包含拼接执行语法（分号、双与符号、管道、命令替换）的命令请求视为不可判定并拒绝，不得拆分后逐段放行。
- **FR-035**: 系统 MUST 为令牌提供目录权限矩阵：以路径前缀为条目，逐条配置读、写、下载、修改四类权限。
- **FR-036**: 系统 MUST 内置系统敏感路径清单（涵盖凭据、私钥、系统账户目录等）；对这些路径的读、写、下载、修改请求 MUST 一律拒绝，且 MUST NOT 允许通过令牌配置放行。
- **FR-037**: 系统 MUST 拒绝既未被矩阵条目覆盖、又不属系统级非敏感路径的请求路径，不得默认放行。
- **FR-038**: 系统 MUST 将系统级非敏感路径的默认权限设为可读与可修改，并允许通过令牌矩阵将其收紧为只读或拒绝。
- **FR-039**: 系统 MUST 按解析后的真实路径判定访问权限，符号链接指向敏感路径时 MUST 按敏感路径处理；含向上穿越语法的路径 MUST 被拒绝。
- **FR-040**: 系统 MUST 按令牌独立存储目录权限矩阵，创建令牌时以全局默认条目初始化，且令牌条目 MUST NOT 超出全局默认范围，只能在其内收紧。
- **FR-041**: 系统 MUST 在审计记录中保留经由令牌发起操作的完整命令原文与输出摘要（前若干字节），并对两者执行敏感信息脱敏。
- **FR-042**: 系统 MUST 在命令原文或输出摘要中检出疑似凭据与私钥内容时，以占位符替换后再写入审计记录，不得原样保存。
- **FR-043**: 系统 MUST 为经由令牌发起的每次命令执行设置时长上限，超时后强制终止并回传已产生的输出摘要；该上限 MUST 独立于会话空闲超时生效，终止后相关资源 MUST 被释放。
- **FR-044**: 系统 MUST 采用左侧主机列表布局：主机清单（含新增入口）位于左侧，点击主机后右侧显示对应终端；MUST NOT 使用顶部导航菜单承载主机与终端切换。
- **FR-045**: 终端区 MUST 支持多会话并存并以顶部 tab 页组织，可切换活动终端；切换时非活动终端 MUST 保持连接不中断。
- **FR-046**: 关闭终端 tab 前系统 MUST 检查该会话是否仍在进行，未结束时 MUST 弹出确认提示；关闭整个页面前若存在活动会话 MUST 同样提示。
- **FR-047**: 审计与令牌功能 MUST 收纳在左下角「设置」入口中，不占用主导航区域。
- **FR-048**: 系统 MUST 支持黑色与白色主题切换并持久化偏好；配色架构 MUST 预留导入外部终端配色方案（如 iTerm 配色文件）的扩展点，但不要求基础版实现导入。
- **FR-049**: 终端 tab MUST 提供右键上下文菜单，含「复制会话」（同一主机新建独立终端会话）与「关闭会话」两项。
- **FR-050**: 主机表单 MUST 统一使用「密码」「密钥」术语，且认证方式切换时 MUST 仅显示当前方式对应的凭据输入框。
- **FR-051**: 每个终端会话 MUST 分配临时会话 ID；双击会话卡 MUST 可修改备注名并按会话 ID 持久化到浏览器本地，MUST NOT 影响服务端主机数据。
- **FR-052**: 复制会话创建后 MUST 立即进入改名编辑态；tab 栏 MUST 提供「新建会话」入口（选择主机后连接）。
- **FR-053**: 会话备注名 MUST 与现有会话卡显示名冲突检查：冲突时拒绝保存并给出提示。
- **FR-054**: 主机分组 MUST 支持点击展开/折叠，折叠状态 MUST 持久化到浏览器本地。
- **FR-055**: 左侧列表呈现为「已保存的会话连接」；右键列表空白处或会话条目 MUST 弹出上下文菜单，含「新建会话连接」入口；新建的连接保存后 MUST 出现在列表中。

### Key Entities *(include if feature involves data)*

- **Host（主机条目）**：代表一台可登录的远程主机；关键属性包括名称、地址、端口、登录用户名、认证方式、分组标签、归属使用者、指纹确认状态。
- **Credential（凭据）**：与主机条目关联的访问凭据（口令或私钥）；始终加密保存，永不以明文形式展示或导出。
- **Session（会话）**：一次终端连接；关联使用者与主机，具有生命周期状态与起止时间，结束时资源必须完全释放。
- **AuditEvent（审计事件）**：连接生命周期中的一次可追溯事件；关联使用者、主机、时间与结果。
- **User（使用者）**：主机条目与会话的归属主体；身份由部署环境提供。
- **MCPToken（MCP 令牌）**：代表一枚供外部工具接入的访问凭证；关键属性包括名称、授权主机范围、操作级别（只读 / 可变更）、有效期、创建时间、最后使用时间与状态（启用 / 已撤销 / 已过期）。明文仅在创建时展示一次，校验信息不可逆保存。操作级别决定该令牌可调用的能力集合：只读级别不含「执行任意命令」能力。令牌另持有一组目录权限条目，共同决定文件访问范围。
- **DirectoryPermission（目录权限条目）**：代表一条以路径前缀为单位的访问规则；关键属性包括路径前缀、读 / 写 / 下载 / 修改四类权限开关、条目来源（全局默认 / 令牌自定义），以及是否为系统级内置条目。系统敏感路径不产生可放行的条目；令牌自定义条目只能在全局默认范围内收紧。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 从点击主机到终端出现可输入提示符不超过 5 秒（网络与目标主机正常）。
- **SC-002**: 在局域网目标主机下，终端输入到回显的感知延迟不超过 200 毫秒。
- **SC-003**: 已保存凭据的主机，重复连接成功率 100%，且无需重新输入凭据。
- **SC-004**: 连接生命周期事件产生审计记录的比例为 100%，无遗漏。
- **SC-005**: 会话结束后，服务端与该会话相关的残留进程数为 0。
- **SC-006**: 未授权来源的终端连接请求被拒绝的比例为 100%。
- **SC-007**: 同一程序在飞牛 fnOS 与通用 Linux 两种形态下，核心用例通过率均为 100%。
- **SC-008**: 首次使用的使用者可在 3 分钟内完成「新增主机 → 打开终端 → 执行一条命令」。
- **SC-009**: 导出的审计记录文件可被人工直接阅读，无需专用工具。
- **SC-010**: 明文凭据在界面、日志、错误信息与导出文件中出现的次数为 0。
- **SC-011**: 从创建令牌到外部工具凭该令牌成功完成一次命令执行不超过 3 分钟（首次配置）。
- **SC-012**: 令牌被撤销或过期后，使用该令牌的请求被拒绝的比例为 100%，且生效延迟不超过 10 秒。
- **SC-013**: 经由令牌发起的操作产生审计记录的比例为 100%。
- **SC-014**: 令牌明文在创建展示之外的任何界面、日志与导出文件中出现的次数为 0。
- **SC-015**: 只读级别令牌发起的命令类请求被拒绝的比例为 100%。
- **SC-016**: 命中危险命令黑名单的请求被拒绝的比例为 100%，可变更级别令牌同样不得放行。
- **SC-017**: 含拼接执行语法的命令请求被拒绝的比例为 100%。
- **SC-018**: 对系统敏感路径的读、写、下载、修改请求被拒绝的比例为 100%，且不因令牌配置而放行。
- **SC-019**: 未被矩阵覆盖且非系统级非敏感路径的访问请求被拒绝的比例为 100%。
- **SC-020**: 经由令牌发起操作的审计记录中，含完整命令原文与输出摘要的比例为 100%。
- **SC-021**: 审计记录中明文凭据与私钥内容出现的次数为 0，检出即以占位符替换。
- **SC-022**: 达到执行时长上限的命令被强制终止的比例为 100%，且终止后残留进程数为 0。

## Assumptions

- 目标使用者为管理少量服务器或 NAS 设备的个人或小型团队，并发会话规模为数十级别，不需要分布式能力。
- 目标主机运行标准 SSH 服务且网络可达，由使用者自行保证可达性。
- 使用者身份由部署环境提供：飞牛形态下来自系统登录态，通用 Linux 形态下由部署方配置的最小访问控制提供；基础版不自建完整用户体系。
- 目标浏览器为现代桌面浏览器；移动端适配不在基础版范围内。
- 基础版不包含会话录像与回放、命令拦截、审批流、用户与主机授权矩阵等堡垒机能力，这些留待后续阶段。
- 基础审计仅提供时间顺序查看与导出，不提供复杂检索与统计界面。
- 数据规模较小（数十台主机、数万条审计记录），文件形态存储足以满足性能要求。
- 部署环境的时间可靠，审计时间以服务端时间为准。
- 审计日志按天或按大小滚动保留，保留天数可在部署时配置，默认为行业常见的短期保留。
- MCP 模式属于基础版 P2：基础版提供令牌管理与外部工具接入，并内置固定的只读命令白名单与危险命令黑名单用于判定；可按令牌自定义的命令策略、命令拦截与审批流仍属后续高级版。
- MCP 令牌默认授予最小权限（默认只读操作级别、默认不覆盖全部主机），更大范围需使用者显式选择。
- 基础版对 MCP 令牌按「主机范围 + 操作级别 + 目录权限矩阵」三个维度控制；命令级判定使用内置固定规则，不支持逐令牌自定义。
- 目录权限矩阵存在一组全局默认条目，在部署时确定，默认不含任何系统敏感路径；令牌创建时以此为初始值。
