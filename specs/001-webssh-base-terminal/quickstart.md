# Quickstart: 本地验证指南

**Branch**: `001-webssh-base-terminal`

用于端到端验证 WebSSH 基础版是否工作。只描述如何跑起来与验证什么，不含实现代码。

## 前置条件

- Node.js 22+
- 一台可登录的 SSH 目标主机（可以是本机）
- 现代桌面浏览器

## 1. 准备目标 SSH 服务

本机可通过系统设置开启「远程登录」（macOS）或安装 `openssh-server`（Linux）。验证：

```bash
ssh <username>@127.0.0.1 -p 22 'echo ok'
```

备用方案：用容器起一个隔离的 sshd：

```bash
docker run -d --name webssh-test-sshd -p 2222:22 linuxserver/openssh-server
```

## 2. 安装与启动（standalone 模式）

```bash
npm install --omit=dev --no-optional
WEBSSH_HOME=~/.webssh-dev npm start
```

预期：日志输出运行模式 `standalone`、监听地址 `127.0.0.1:8080`，并自动创建数据目录（权限 0700）。

## 3. 验证主机与凭据管理

1. 打开 `http://127.0.0.1:8080`
2. 新增主机：填写名称、地址、端口、用户名，选择口令或私钥认证并保存
3. 刷新页面 → 主机仍在清单中；查看与编辑时**不显示明文凭据**
4. 检查 `~/.webssh-dev/etc/hosts.json` → 凭据为密文结构（`alg` / `iv` / `tag` / `data`）
5. 删除该主机 → 清单与文件中均不再包含它

## 4. 验证终端会话

1. 点击该主机 → 5 秒内出现可输入提示符
2. 执行 `whoami` → 回显目标主机的用户名
3. 拖动改变浏览器窗口大小 → 执行 `tput cols` 与 `tput lines`，数值随窗口变化
4. 执行一条持续输出的命令后按 `Ctrl+C` → 输出中断，回到可输入状态
5. 直接关闭标签页 → 服务端日志显示会话结束；检查服务端无残留 SSH 连接

## 5. 验证主机指纹确认

1. 新增一台此前未连接过的主机并连接 → 提示指纹待确认，不直接连上
2. 确认后连接成功；`etc/known_hosts` 中出现该主机记录
3. 人为改动该主机密钥后重连 → 被拒绝并提示指纹变化

## 6. 验证审计

1. 分别制造一次成功连接、一次认证失败、一次空闲超时断开
2. 打开审计页面 → 三条记录按时间顺序排列，含操作者、时间、主机、结果、时长、断开原因
3. 导出审计 → 文件可直接用文本编辑器阅读
4. 全文搜索审计文件 → 无明文口令或私钥内容

## 7. 验证 MCP 令牌（P2）

1. 创建一枚令牌：名称自定、级别选 `readonly`、主机范围选一台、目录权限保持默认
2. 记录**仅出现一次**的令牌明文
3. 用支持 MCP 的客户端配置该令牌并连接
4. 调用列表工具 → 只看到授权范围内的主机
5. 尝试调用命令类工具 → 该工具不存在（只读令牌未注册）
6. 再创建一枚 `writable` 令牌，执行 `ls /var/log` → 成功；执行 `rm -rf /tmp/x` → 被拒绝
7. 尝试读取敏感路径（如 `/etc/shadow`）→ 被拒绝
8. 撤销令牌后重试 → 请求立即被拒绝
9. 查看审计 → 每条调用均有记录且标明令牌；命令原文与输出摘要已脱敏

## 8. 验证 fnOS 模式

1. 按 `packaging/fnos/` 下的应用包目录构建 `.fpk`
2. 在飞牛设备上手动安装并打开桌面入口
3. 重复第 3–6 节的验证步骤，结果应一致
4. 确认服务端日志输出的运行模式为 `fnos`，监听形态为 Unix Socket

## 9. 验证双模式一致性

同一份代码分别以 standalone 与 fnos 启动，核心用例（新增主机 → 打开终端 → 执行命令 → 查看审计）通过率应均为 100%。

## 10. 清理

```bash
docker rm -f webssh-test-sshd   # 若使用了容器
rm -rf ~/.webssh-dev
```
